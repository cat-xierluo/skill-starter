## 核心概念：模板是什么

模板（template）是一个**预置好目录骨架和协作文档的起点**。你把它复制一份、改名、填内容，就能得到一个结构规范的 Skill，不用从零想目录结构。

模板的位置：`skills/skill-template/`。

### 目录结构总览

复制模板后你会得到这些文件，每个都有明确用途：

| 文件 / 目录 | 用途 | 必选？ | 说明 |
| :--- | :--- | :--- | :--- |
| `SKILL.md` | Skill 的定义文件（触发命根子） | **必选** | frontmatter + 正文，AI 靠它发现和触发 Skill |
| `scripts/` | 存放脚本 | 按需 | 带脚本型 Skill 用（07）；纯说明型可删（06） |
| `references/` | 存放按需加载的详细资料 | 按需 | 正文放不下的细节放这里，AI 不会自动全读 |
| `assets/` | 存放模板和静态资源 | 按需 | 配置模板、示例数据等 |
| `LICENSE.txt` | 许可证文本 | **推荐** | 对外共享时必备；见 [01-概念入门/02-什么是-许可证](../01-概念入门/02-什么是-许可证.md) |
| `CHANGELOG.md` | 对外可见的变更记录 | **推荐** | 按版本号记录变更，见 [04 调试与发布](./04-调试与发布.md) |
| `ROADMAP.md` | 路线图 | 可选 | 记录阶段目标和里程碑 |
| `TASKS.md` | 当前待办 | 可选 | 记录要做什么、做完什么 |
| `DECISIONS.md` | 决策记录 | 可选 | 记录为什么这么做 |
| `.env.example` | 环境变量模板 | 按需 | 涉及密钥时用（真值放 `.env`，被 `.gitignore` 忽略） |
| `.gitignore` | 忽略规则 | **推荐** | 默认忽略 `.env` / `output/` 等 |

一句话记忆：**SKILL.md 是命根子，LICENSE + CHANGELOG 是对外脸面，scripts/references/assets 是干活零件，ROADMAP/TASKS/DECISIONS 是协作文档**。

### frontmatter 全字段

SKILL.md 开头的 `---` 之间是 frontmatter（元数据），AI 用它来识别和触发 Skill：

```yaml
---
name: your-skill-name       # 必填：英文唯一标识，必须和目录名一致
description: |              # 必填：AI 靠它判断要不要触发
  本技能应在...时使用。
  不要用于：...。
license: MIT                # 推荐：许可证标识（需与 LICENSE.txt 一致）
homepage: https://...       # 可选（扩展字段）：项目主页
author: your-name           # 可选（扩展字段）：作者
version: 1.0.0              # 可选（扩展字段）：版本号
---
```

三个要点：

1. **`name` 必须和目录名一致**——否则 `scripts/check_skills.py` 会报错（本仓库 CI 强制检查）。
2. **`description` 是触发的命根子**——写法的深度见 [06](./06-纯说明型-Skill.md) 和 [09 触发质量与 eval](./09-触发质量与eval.md)。
3. **`license` 要和 `LICENSE.txt` 一致**——不能 frontmatter 写 MIT、LICENSE.txt 放 Apache。

扩展字段（homepage / author / version）是各平台（Claude / Codex / OpenClaw）的补充，本仓库校验器兼容它们，不会因扩展字段报错（见 `scripts/check_skills.py`）。

## 实例分析：模板里每个文件长什么样

打开 `skills/skill-template/`，你会看到：

**SKILL.md**——模板的 SKILL.md 是一个带注释的骨架，告诉你每个段落写什么（适用场景 / 快速开始 / 与其他技能配合 / 示例）。复制后把占位内容换成你的。

**scripts/main.py**——一个能直接跑的脚手架脚本（`#!/usr/bin/env python3`），带退出码约定。带脚本型 Skill 从这里改；纯说明型直接删掉整个 `scripts/` 目录。

**.env.example**——只有占位值（`API_KEY=`、`MODEL_NAME=`），提醒你「真值放 .env，别提交」。涉及密钥时才用，见 [02-工具指南/09-环境变量与密钥安全](../02-工具指南/09-环境变量与密钥安全.md)。

**CHANGELOG.md / ROADMAP.md / TASKS.md / DECISIONS.md**——协作文档模板，格式照搬本仓库（见根目录的同名文件）。复制后把内容清空、填你自己的。

**.gitignore**——默认忽略 `.env`（密钥）、`output/`（运行产物）、`__pycache__/`（Python 缓存）。

## 创建流程导航：8 步把模板变成 Skill

下面是完整的创建流程，每一步都指向讲细节的具体篇——**本篇只给导航，不重复讲细节**。

### 第 1 步：复制模板并改名

```bash
# 在 starter 仓库内创建
cp -r skills/skill-template skills/<你的-skill-名>

# 或单独建仓库
cp -r skills/skill-template ../<你的-skill-名>
```

跨平台提示：macOS / Linux 直接敲；Windows 用 `Copy-Item -Recurse`（PowerShell）或在 Git Bash 里用 `cp -r`（见 [02-工具指南/06-终端与命令行入门](../02-工具指南/06-终端与命令行入门.md)）。

### 第 2 步：按规范命名

目录名即 Skill 名，遵循「行为-对象」或「对象-行为」格式：

- ✅ `github-issues`（行为-对象）
- ✅ `image-understand`（对象-行为）
- ❌ `do-something-useful`（太泛）

用英文（社区通用），1-2 个单词最佳，不看描述也能猜到用途。

### 第 3 步：写 frontmatter

改 `name`（和目录名一致）、写 `description`（触发命根子）、确认 `license`。frontmatter 全字段见本篇「核心概念」。`description` 的写法深度见 [06 纯说明型 Skill](./06-纯说明型-Skill.md)。

### 第 4 步：选择 Skill 类型

根据任务决定形态，然后去对应篇学具体怎么造：

| 任务特征 | 选哪种 | 去哪篇 |
| :--- | :--- | :--- |
| AI 光靠「想」能完成（教知识/规范/流程） | 纯说明型 | [06 纯说明型 Skill](./06-纯说明型-Skill.md) |
| 必须读文件、跑命令、算结果 | 带脚本型 | [07 带脚本 Skill](./07-带脚本-Skill.md) |
| 要把好几个 Skill 串成一条流程 | 多 Skill 编排 | [08 多 Skill 编排](./08-多Skill编排.md) |

不确定时先做纯说明型——能用知识解决的别急着写脚本（脚本意味着依赖、跨平台、退出码契约，维护成本立刻上来）。

### 第 5 步：实现内容

按你选的类型，照对应篇的「动手步骤」实现。纯说明型写 SKILL.md + references；带脚本型加 scripts；编排型加 references/workflow.md。

### 第 6 步：补协作文档

确认 `CHANGELOG.md`（记第一个版本 `0.1.0`）、`LICENSE.txt`（和 frontmatter license 一致）适合当前项目。ROADMAP/TASKS/DECISIONS 按需保留。格式参照 [04 调试与发布](./04-调试与发布.md) 和本仓库根目录同名文件。

### 第 7 步：本地测试与触发质量

跑 `bash scripts/check.sh`（在 starter 根目录）确认结构合法、链接有效。触发质量（该触发时触发、不该触发时不误触）的系统评估见 [09 触发质量与 eval](./09-触发质量与eval.md)。

### 第 8 步：调试与发布

完整流程（错误诊断、版本、tag、安装说明、回滚）见 [04 调试与发布](./04-调试与发布.md)。

## 常见错误

下面 6 条按症状命名，展开说为什么错、怎么改。

### 目录名和 `name` 字段不一致

目录叫 `my-skill`，frontmatter `name: my_tool`——`scripts/check_skills.py` 会报错，AI 发现 Skill 时也会混乱。改法：两者严格一致，用同一个英文标识。

### 删了 `scripts/` 但正文还引用

做纯说明型时删了 `scripts/` 目录，但 SKILL.md 正文还写着「调用 `scripts/main.py`」——AI 照做会找不到文件。改法：删 `scripts/` 的同时，把正文里所有对脚本的引用一起删（见 [06 纯说明型 Skill](./06-纯说明型-Skill.md) 的「从模板删掉用不上的部分」）。

### `license` 字段和 `LICENSE.txt` 矛盾

frontmatter 写 `license: MIT`，但 `LICENSE.txt` 放的是 Apache 文本——使用者不知道该信哪个。改法：两者严格一致；不确定时见 [01-概念入门/02-什么是-许可证](../01-概念入门/02-什么是-许可证.md)。

### 把所有内容塞进 SKILL.md

把全部细节都写进 SKILL.md 正文，导致文件超大、AI 加载成本高。改法：SKILL.md 只放最常用的 20%，细节拆进 `references/`，并在正文引导 AI 去看（references 不会被自动全读）。

### `references/` 放了资料但正文不引导

把详细文档放进 `references/`，但 SKILL.md 正文完全没提到它——AI 不知道有这个文件，不会去读。改法：在正文相应位置写「详见 references/xxx.md」（见 [01-概念入门/06-一个-Skill-是怎样工作的](../01-概念入门/06-一个-Skill-是怎样工作的.md)）。

### 协作文档照搬模板不改

复制了 CHANGELOG/ROADMAP/TASKS/DECISIONS，但内容还是模板的占位文本（「YYYY-MM-DD」「待完成」）——发布后显得不专业。改法：复制后立即清空占位内容，填你自己的第一个版本和待办。

## 自测题 / 验收

1. **目录结构**：`skills/skill-template/` 里哪些文件是必选的？哪些是推荐的？各说一个理由。
2. **frontmatter**：`name` 字段有什么强制要求？为什么？`description` 为什么被称为「触发命根子」？
3. **命名**：给「自动生成周报」这个需求起一个符合规范的 Skill 名，并说明是行为-对象还是对象-行为。
4. **类型选择**：需求是「帮我把团队 commit 规范教给 AI，让它写提交时按格式来」——该选纯说明型还是带脚本型？为什么？去哪篇学具体怎么做？
5. **流程导航**：你要造一个带脚本型 Skill，从复制模板到发布，按本篇 8 步分别要去哪些篇？能列出来吗？

第 4 题能判断出「纯说明型（教规范，AI 光靠想能完成）→ 去 06」，说明你已经掌握了模板创建的类型决策。
