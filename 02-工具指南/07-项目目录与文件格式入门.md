# 项目目录与文件格式入门

这篇解决一件事：

**让你看懂一个项目文件夹里都有什么、为什么有些文件平时看不见、`.md` / `.yml` / `.json` 这些后缀各自是什么、以及 UTF-8 和缩进为什么重要。**

---

## 本篇目标

读完你应该能：看懂典型项目目录结构；解释 `.git/`、`.env`、`.gitignore` 为什么平时看不见；看懂并会改 Markdown、YAML、JSON；知道 frontmatter 是什么；理解 UTF-8 和缩进为什么影响“能不能正常打开 / 解析”；完成几个可上手的小练习。

## 前置知识

读过 [终端与命令行入门](./06-终端与命令行入门.md)：会用 `ls -a` 看隐藏文件、看懂路径。知道“文件有不同类型”。

## 核心概念

### 一个项目目录长什么样

打开任意代码项目，常见结构类似：

```text
my-project/
├── README.md
├── package.json
├── .gitignore
├── docs/
├── scripts/
└── .git/        ← 平时看不见
```

- `README.md`：项目“说明书”，仓库网页第一眼看到的就是它。
- `package.json` / `requirements.txt`：声明项目依赖（见 [开发环境与依赖入门](./08-开发环境与依赖入门.md)）。
- `.gitignore`：告诉 Git 哪些文件不纳入版本管理（见 [Git 入门](./01-Git-入门.md)）。
- `.git/`：Git 的“数据库”，存全部历史，平时不显示，也**不要手动改它**。

### 隐藏文件

文件名以 `.` 开头的文件或文件夹默认隐藏，常见有：`.git/`（版本库元数据）、`.env`（环境变量，常放密钥 / Token，**不要提交进 Git**）、`.gitignore`（忽略清单）、`.claude/` / `.vscode/`（工具配置）。它们被隐藏不是为保密，而是日常不必打扰你。终端里默认 `ls` 看不到，要加 `-a`；PowerShell 用 `ls -Force`。

### 扩展名

扩展名（点号后的部分）提示文件格式和打开方式：`.md` 是 Markdown（人读、网页渲染），`.yml` / `.yaml` 和 `.json` 是配置 / 数据（程序解析），`.sh` 是 shell 脚本，`.py` 是 Python 源码。再记住一个大类区分：**文本文件**（`.md` / `.json` / `.py`，编辑器能直接读懂）和**二进制文件**（图片、压缩包、程序，打开是乱码）。本篇只讲文本文件。

## 动手步骤（含小练习）

建议新建一个 `format-demo` 文件夹放练习。

### 练习一：Markdown

核心语法：行首 `#` 数量表示标题层级；`-` / `*` 是无序列表，`1.` 是有序列表；`**文字**` 是粗体；反引号包起来是行内代码（如 `` `ls -a` ``）；三个反引号围起来是代码块。

行内链接的写法是“方括号里写显示文字，紧接着圆括号里写目标”。例如下面这句就指向本仓库一个真实文件：

[Git 入门](./01-Git-入门.md)

也就是：前面方括号里的字会显示出来，后面圆括号里写目标路径或网址。

小练习一：新建 `notes.md`，写一个一级标题、一段加粗的话、一个无序列表，再加一条指向 `./01-Git-入门.md` 的链接，保存后用任意 Markdown 预览看效果。

### 练习二：YAML

YAML 用缩进表示层级，靠键值对和列表组织，比 JSON 更适合人手写。本仓库每个 Skill 的 `SKILL.md` 开头那段就是 YAML：

```yaml
---
name: my-skill
description: 这个 Skill 做什么、什么时候触发
---
```

规则：键值对写 `键: 值`，冒号后要有**一个空格**；层级靠缩进，**只能用空格、不能用 Tab**；同级要对齐；列表每项以 `- ` 开头。

小练习二：把上面 `description` 改成你自己的话，注意冒号后留空格、缩进不变。

### 练习三：JSON

JSON 比 YAML 严格，但机器解析最稳，程序间传数据常用：

```json
{
  "name": "my-project",
  "version": "1.0.0",
  "tags": ["docs", "starter"],
  "ready": true
}
```

规则（和 YAML 很不一样，踩坑高发区）：字符串**必须用双引号**；键也要双引号；**不能写注释**；最后一个元素后**不能有尾逗号**；对象用 `{}`，数组用 `[]`。

小练习三：在上面 JSON 里加一行 `"author": "你的名字"`，注意它前一行 `"ready": true` 末尾要补逗号。

### frontmatter

frontmatter 是“正文前面那段元数据”，即开头被 `---` 包住的 YAML，用来给文件挂结构化标签（名字、描述、日期），让程序能批量读取。注意 `---` 是三个英文半角减号，**别打成中文破折号**，否则解析失败。

### 编码与缩进

编码决定文字怎么存成字节，中文最常踩的坑是换台电脑或放进 Git 就乱码。解决办法统一存 **UTF-8**（现代编辑器默认就是；乱码时在编码选项切回 UTF-8 再保存，建议“无 BOM”）。缩进对 YAML、Python 是“语法的一部分”，错了就解析失败：每级用 **2 个空格**（本仓库统一 2 空格），YAML 里别混用 Tab 和空格，在编辑器打开“Tab 转空格”最省心。

## 常见错误

- YAML 用了 Tab 缩进：换成空格。
- YAML 同级没对齐：少缩 / 多缩一格层级就错乱。
- JSON 用了单引号或尾逗号：双引号、无注释、无尾逗号。
- frontmatter 的 `---` 打成中文破折号：用三个英文半角减号。
- Markdown 代码块前后没空行：上下各留一空行最稳。
- 文件名带空格或全中文：优先英文小写加连字符。
- 改完文档链接写错：本仓库有自检脚本查相对链接，改完跑 `bash scripts/check.sh`。

## 自测题 / 验收

1. 说出 `.git/` 为什么平时看不见、为什么不能手动改。
2. 区分 YAML 和 JSON 的三个差异（缩进对括号、能否注释、引号要求）。
3. 在一个 `.md` 里正确加标题、列表、加粗和一条指向真实文件的链接。
4. 改掉一段 frontmatter 的 `description` 而不破坏格式。
5. 解释为什么文本文件要统一 UTF-8、缩进用空格。
6. 进阶：跑一次 `bash scripts/check.sh` 确认新链接有效。
