# 开发环境与依赖入门

这篇解决一件事：

**让你不再被“环境”吓到——能确认电脑装没装 Python / Node.js、装了哪个版本，会装第三方库，听懂“虚拟环境”“全局安装 vs 项目安装”“npx”在说什么。**

---

## 本篇目标

读完你应该能：说清“运行时”“依赖”“包管理器”；查 Python 和 Node.js 的版本；用 pip 装一个库并用虚拟环境隔离；用 npm 装项目依赖；用 npx 临时跑一个包；解释“全局安装 vs 项目安装”及为什么默认推荐项目安装。版本与平台信息最近核对：2026-07。

## 前置知识

读过 [终端与命令行入门](./06-终端与命令行入门.md)：会开终端、看路径、查退出码。读过 [项目目录与文件格式入门](./07-项目目录与文件格式入门.md)：知道 `package.json` / `requirements.txt` 的作用。

## 核心概念

### 运行时

Python 代码不能直接被系统执行，需要 Python 解释器；Node.js 代码需要 Node 运行时。这类“能跑某种代码的基础程序”叫运行时。版本间差异可能很大，截至 2026-07 常见稳定区间：Python 为 3.12 / 3.13 / 3.14（务必用 Python 3，不要用已停维的 Python 2）；Node.js 为 22 或 24 的 LTS（20 系列已接近停维）。“最新”会变，更重要的是**会自己查版本**。

### 依赖与包管理器

项目几乎都会用到别人写好的库（发请求、解析 JSON、处理日期…），这些库就是依赖，通常列在一个文件里：Python 用 `requirements.txt`（或 `pyproject.toml`），Node 用 `package.json`。别人照着装一遍就能得到几乎一样的环境。装库靠包管理器：Python 是 `pip`（装 Python 时自带），Node 是 `npm`（装 Node 时自带），它们连到公共仓库取包。

### 全局安装 vs 项目安装

装一个包有两种范围：**全局安装**装一次整台电脑都能用，但不同项目可能要不同版本、全局只能留一个，容易打架、还可能污染系统；**项目安装**只装到当前项目、彼此隔离，**默认推荐这种**。Python 的项目安装靠虚拟环境实现，Node 的项目安装天然把包装进 `node_modules/`。`npx` 是 npm 自带的小工具，临时下载并运行某个包、跑完即走，常用于跑 `create-xxx` 脚手架。

## 动手步骤

### 第一步：查 Python

```bash
python3 --version
pip3 --version
```

macOS / Linux 命令多是 `python3` / `pip3`，Windows 多是 `python` / `pip`。报 `command not found` 就去 [python.org](https://www.python.org) 下官方安装器；macOS 也可 `brew install python`，Linux 用发行版包管理器。

### 第二步：查 Node.js

```bash
node --version
npm --version
```

`node --version` 输出类似 `v22.x.x`。没装就去 [nodejs.org](https://nodejs.org) 下 LTS 版；macOS 也可 `brew install node`。

### 第三步：Python 虚拟环境 + 装包

虚拟环境给每个项目一套独立库，建议每个 Python 项目都用：

```bash
mkdir env-demo
cd env-demo
python3 -m venv .venv       # 建隐藏的 .venv 文件夹
```

激活（提示符前会多一个 `(.venv)`）：

```bash
# macOS / Linux / Git Bash
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

装包并记录依赖：

```bash
pip install requests
pip freeze > requirements.txt
deactivate          # 退出虚拟环境
```

`.venv` 只属于这台电脑，不要提交进 Git，在 `.gitignore` 加 `.venv/`（见 [Git 入门](./01-Git-入门.md)）。

### 第四步：npm 项目安装

```bash
mkdir node-demo
cd node-demo
npm init -y             # 生成默认 package.json
npm install lodash      # 装一个项目级依赖
```

装完后 `package.json` 的 `dependencies` 多了 `lodash`，并多出 `node_modules/`（所有包在这）和 `package-lock.json`（锁定版本）。`node_modules/` 体积大且能由 `package.json` 重新生成，**不要提交进 Git**，`.gitignore` 加 `node_modules/`。

### 第五步：npx 临时跑

```bash
npx cowsay "hello"
```

没装过 `cowsay` 的话，npx 会临时下载、跑一次、不留在全局——用完即走。

### 全局 vs 项目安装 对照

| 维度 | 全局安装 | 项目安装（推荐） |
|------|----------|------------------|
| 范围 | 整台电脑 | 只在当前项目 |
| 版本冲突 | 容易打架 | 各项目独立 |
| 复现性 | 差 | 好（靠 lock 文件） |
| 典型命令 | `npm i -g xxx` 或全局 `pip install` | `npm i xxx` 或虚拟环境内 `pip install` |

进阶：不同项目要不同版本时，可用版本管理器（Node 的 `nvm` / `fnm`，Python 的 `pyenv`），新手知道有即可。

## 常见错误

- `python: command not found`：命令名不同（macOS / Linux 多 `python3`，Windows 多 `python`），先确认名字和 PATH。
- `pip install` 报 externally-managed-environment：较新 macOS / Linux 拒绝往全局装包，**正确做法就是用虚拟环境**。
- 忘了激活虚拟环境就装包：装到了全局 / 系统，污染别的项目。装包前先看提示符有没有 `(.venv)`。
- 把 `node_modules/` 或 `.venv` 提交进 Git：写进 `.gitignore`。
- 版本不匹配报错（如 `SyntaxError`、API 不存在）：按 `requirements.txt` / `package.json` 重装依赖。
- Windows 上用了 `source`：PowerShell 用 `.venv\Scripts\Activate.ps1`，或改用 Git Bash。

## 自测题 / 验收

1. 打出电脑上 Python 和 Node.js 的版本号。
2. 说出 Python 和 Node 各自的包管理器。
3. 建一个 Python 虚拟环境，装一个包并记进 `requirements.txt`。
4. 用 npm 装一个项目级依赖，并解释 `node_modules/` 为什么不该进 Git。
5. 解释“全局安装 vs 项目安装”及默认推荐哪个。
6. 进阶：用 `npx` 临时跑一个包，说明它和全局安装的区别。

开发环境与依赖的核心不是“装一堆东西”，而是：
