# 什么是 AGENTS.md 和 CLAUDE.md

## 本篇目标

读完这篇，你应该能做到：

1. 用一句话说清 `CLAUDE.md`、`AGENTS.md`、`.claude/settings.json`、`SKILL.md` 各自管什么。
2. 拿到一段内容，能判断它该写进哪个文件，而不是全堆进 `CLAUDE.md`。
3. 说明「规则只写一份、再喂给 Claude」这种做法的好处，避免维护两套不一致的规则。
4. 知道哪些信息**不能**写进会被提交进 Git 的记忆文件（尤其密钥）。

本篇是概念辨析篇（讲清楚几个容易混淆的文件分别是什么），不涉及具体编写语法；怎么把规则写好是 [Rules 编写指南](./04-Rules-编写指南.md) 的事。

## 前置知识

读这篇前，建议你已经了解：

- [什么是 Vibe Coding](./01-什么是-Vibe-Coding.md)：理解「人描述目标、AI 推进实现」的分工。
- 知道项目里常见的几个文件类型：`AGENTS.md`、`CLAUDE.md`、`settings.json` 是纯文本/配置文件，照抄示例即可，无需预先掌握；想系统学先看 [项目目录与文件格式入门](../02-工具指南/07-项目目录与文件格式入门.md)。

---

在 AI Coding 项目里，很多人会看到这些文件：

- `AGENTS.md`
- `CLAUDE.md`
- `.claude/settings.json`

它们都和“上下文”有关，但职责不一样。

## 先理解一句话

这些文件本质上是在回答：

**AI 进入这个项目后，应该知道什么、遵守什么、怎么工作。**

## `CLAUDE.md` 是什么

`CLAUDE.md` 是 Claude Code 官方支持的“项目记忆文件”。

根据 Claude Code 官方文档：

- `./CLAUDE.md` 或 `./.claude/CLAUDE.md` 可以作为项目级说明
- Claude 会在会话开始时自动读取这些说明
- 它适合写项目规则、常用命令、架构约定、命名习惯、工作流说明

你可以把它理解成：

> 给 Claude Code 的项目级入职说明。

### 适合写什么

- 怎么启动项目
- 怎么跑测试
- 代码风格
- 哪些目录重要
- 常见工作流
- 项目内必须遵守的规则

### 不适合写什么

- 临时性的个人偏好
- 密钥
- 大段重复文档

## `AGENTS.md` 是什么

`AGENTS.md` 不是 Claude Code 的唯一官方保留文件名，但在很多 AI Coding 项目里，它会被当作：

> 面向 AI 代理的协作协议文件。

在这个 starter 仓库里，`AGENTS.md` 的职责是：

- 规定文档怎么写
- 规定目录怎么命名
- 规定 Git 工作流
- 规定哪些文档必须同步更新

也就是说，它更偏：

- 仓库协作规则
- 代理行为规范
- 团队约定

### 你可以把它理解成

- `CLAUDE.md`：Claude Code 自动加载的项目记忆
- `AGENTS.md`：团队写给 AI 代理看的协作章程

## 它们有什么区别

| 文件 | 主要角色 | 更像什么 | 是否官方自动加载 |
|------|----------|----------|------------------|
| `CLAUDE.md` | Claude Code 项目记忆 | 项目说明书 | 是 |
| `AGENTS.md` | 代理协作协议 | 团队规则手册 | 不一定，取决于工具 |

## 在这个项目里为什么两个都有

看当前仓库的 [CLAUDE.md](../CLAUDE.md)，你会发现它几乎只是：

```md
@include ./AGENTS.md
```

这说明本项目采用的是：

1. 把主要协作规则写在 `AGENTS.md`
2. 再通过 `CLAUDE.md` 把这些规则喂给 Claude Code

这样做的好处是：

- 规则只有一份，不容易写两套
- 既能给人看，也能给 Claude 读
- 项目上下文更集中

## 还有哪些“上下文文件”

### `.claude/settings.json`

这是配置文件，不是说明文档。

它主要控制：

- 权限
- 工具行为
- 环境变量
- 本地或团队设置

例如官方文档里提到，可以用它禁止 Claude 读取 `.env` 等敏感文件。

### `SKILL.md`

这是 Skill 本身的定义文件。

它解决的是：

> 某个 Skill 什么时候触发、怎么工作、依赖什么资源。

### `CHANGELOG.md` / `ROADMAP.md` / `TASKS.md` / `DECISIONS.md`

这些不是 Claude 的底层配置文件，但会成为非常重要的项目上下文来源。

它们回答的是：

- 改过什么
- 计划做什么
- 当前要做什么
- 为什么这样做

## 新手最实用的理解方式

如果把一个 AI Coding 项目想成“让 AI 入职一个团队”，那么：

- `CLAUDE.md` = 入职须知
- `AGENTS.md` = 团队规章制度
- `.claude/settings.json` = 系统设置与权限
- `SKILL.md` = 某个岗位/能力包的说明书
- `TASKS.md` / `DECISIONS.md` = 项目进展与决策记录

## 推荐实践

### 对单个项目

至少保留：

- `CLAUDE.md`
- `AGENTS.md` 或等价协作协议
- `CHANGELOG.md`
- `TASKS.md`
- `DECISIONS.md`

### 对复杂团队项目

建议：

- `CLAUDE.md` 只放 Claude 真的需要的项目说明
- `AGENTS.md` 放完整协作协议
- 长文档不要全塞进 `CLAUDE.md`
- 敏感信息不要写进任何会被提交的记忆文件

## 常见错误

### 规则只写进 `CLAUDE.md`，没写进 `AGENTS.md`

后果：规则只对 Claude Code 这一个工具生效。换成别的 AI Coding 工具，或别人用别的客户端打开仓库，规则就丢了。

对策：把「换任何工具都该遵守」的协作规则写进 `AGENTS.md`，再用本仓库这种 `@include ./AGENTS.md` 的方式把它喂给 Claude，做到「规则只有一份，多工具共享」。

### 把密钥写进会被提交进 Git 的记忆文件

后果：API Key、Token 这类凭据一旦写进 `CLAUDE.md` / `AGENTS.md` 并 `git push`，等于公开泄露（即使事后删除，历史提交里仍能找到）。

对策：密钥只放 `.env`、本地不提交的 `.claude/settings.json`，或环境变量；并确保 `.gitignore` 覆盖这些文件。`CLAUDE.md` 的「不适合写什么」也明确列了「密钥」。

### 把大段文档全塞进 `CLAUDE.md`

后果：`CLAUDE.md` 越来越长又乱，真正重要的启动命令、关键目录反而不显眼，AI 也会抓不到重点。

对策：`CLAUDE.md` 只放 Claude 真正每次都需要的项目说明（启动方式、跑测试、核心约定）；长文档单独成文，用链接引用，按需加载。

### `AGENTS.md` 和 `CLAUDE.md` 维护两套内容，导致不一致

后果：同一件事在两个文件里说法不同，AI 不知道听哪个，人也搞不清哪个是准的。

对策：规则只写一份。本仓库的做法是「主要规则写在 `AGENTS.md`，`CLAUDE.md` 只用 `@include` 引用它」，就是为了避免两套来源互相打架。

### 把权限、环境变量当说明文字写进 `CLAUDE.md`

后果：你「希望」禁止某行为，但只是用自然语言提了一句，工具并不会真的强制执行。

对策：权限、工具行为、环境变量这类**机器要执行**的配置，写进 `.claude/settings.json`；给 Claude 看的「说明」写进 `CLAUDE.md`。别把「配置」和「说明」混在一起。

## 自测题

下面 3 题考的是文件归属的判断。每段内容该放进哪个文件？答案要点附后。

1. 你想让 Claude 在本项目里「文档统一用中文、commit message 用 `type: summary`、不要提交 `.env`」。这段内容该写进哪个文件？

   **答案要点**：写进 `AGENTS.md`（团队协作协议，换工具也该遵守），再用 `CLAUDE.md` 的 `@include` 喂给 Claude。这些是「规则内容」，载体可以是 `AGENTS.md`。

2. 下面三段内容，分别该放进 `CLAUDE.md`、`AGENTS.md`、`.claude/settings.json` 中的哪一个？
   - A：「禁止读取 `.env`、`.env.local` 等敏感文件」
   - B：「本项目用 `npm test` 跑测试，入口在 `src/index.ts`」
   - C：「所有教程文章必须含『本篇目标 / 前置知识 / 常见错误 / 自测题』四段」

   **答案要点**：A → `.claude/settings.json`（这是要工具强制执行的权限/行为配置，不是说明）；B → `CLAUDE.md`（Claude 每次都需要的项目启动说明）；C → `AGENTS.md`（团队文档协作规则，换工具也该遵守）。

3. 判断对错并说明理由：「我把 OpenAI 的 `sk-fake-DEMO1234` 写进 `CLAUDE.md`，反正只要不 push 到公开仓库就没事。」

   **答案要点**：错（且很危险）。`CLAUDE.md` 默认会被提交进 Git，只要哪天手滑 push 或仓库改成公开，密钥就泄露了，且历史提交仍可恢复。密钥应放 `.env` / 本地 `settings.json` / 环境变量，并确保被 `.gitignore` 忽略。

## 一句话总结

`CLAUDE.md` 是 Claude Code 的官方项目记忆入口，`AGENTS.md` 是团队给 AI 代理的协作规则。两者配合得好，项目上下文才会稳定。
