# 什么是 Skill？

## 本篇目标

读完这篇，你能：

- 用一句话说清 Skill 是什么、它和手机 App 的类比关系；
- 分清 Skill、Plugin、Extension 这几个经常被混着用的词；
- 说出 Skill 为什么重要（4 个理由），并能在日常工作中举出 2-3 个真实场景；
- 知道一个 Skill 不是「装上就能用」，它还要经历「被发现、被触发、被执行、出结果、也可能失败」这些阶段（只到概念名词层，机制细节放到后面两篇）；
- 判断自己什么时候该往下一篇（05 或 06）继续学深度。

这是「概念入门」系列的第一篇，目标只有一个：**让你先建立印象**，知道 Skill 大致是个什么、它能干嘛、它大致怎么运作。至于「怎么和工具/MCP/Plugin 区分」「内部到底怎么跑」，留给 05 和 06。

## 前置知识

无。这是概念入门系列的第一篇，零基础起步，不需要你先懂命令行、Git、Python 或任何编程概念。

## 核心概念：Skill 是什么

### 类比：Skill 就像手机 App

想象你的手机：

- **没有 App 时**，只能打电话、发短信——一台功能机；
- **装了微信 App**，能聊天、视频、支付；
- **装了美团 App**，能点外卖、订酒店。

AI（人工智能助手）也是一样：

- **没有 Skill 时**，只能简单对话、回答问题，干不了「动手」的活；
- **装了「飞书」Skill**，能帮你管理日历、读写文档；
- **装了「GitHub」Skill**，能帮你操作代码仓库、看 issue。

> Skill（技能）就是给 AI 装的「App」。它让一个只会「想和说」的大脑，长出「手脚」去真做事。

### Skill vs Plugin vs Extension

这三个词经常被混着用，但侧重点不同：

| 概念 | 定位 | 类比 | 一句话区别 |
|------|------|------|------------|
| **Skill** | 给 AI 装的能力扩展包 | 手机 App | 强调「这份能力本身」 |
| **Plugin**（插件） | 给某个宿主程序装的扩展模块 | 相机 App 里的滤镜插件 | 强调「装进软件、可分发」 |
| **Extension**（扩展） | 通常是浏览器扩展 | Chrome 扩展 | 强调「挂到浏览器这个宿主上」 |

一个关键点：同一份「代码审查」能力，挂在 AI 助手里按需加载时叫 Skill，挂到某个 IDE 的插件市场里分发时叫 Plugin，挂到浏览器上时叫 Extension——**东西可以是同一个，叫法随它挂在哪、怎么装而定**。在本教程里，我们统一用「Skill」来描述这份能力本身。

> 想深入看 Skill 和工具、MCP、Plugin、Workflow 的层级关系，见 [工具、Skill、MCP、Plugin、Workflow 到底什么关系？](./05-工具-Skill-MCP-Plugin-Workflow-关系.md)。

### 为什么 Skill 很重要？

通用 AI（不装任何 Skill 的 AI）像「百科全书」——什么都懂一点，但什么都不精，而且没有手脚。Skill 解决的正是这两件事：

1. **专业化**：通用 AI 啥都会但都不精，Skill 让 AI 在某个特定领域（比如飞书日历、代码审查）变成专家；
2. **自动化**：Skill 不只是「会说」，它还能调用工具，帮你把一件事从头到尾做完；
3. **可复用**：写一次 Skill，全团队、全公司都能用，不用每个人重新教 AI 一遍；
4. **可组合**：多个 Skill 可以配合使用，1+1>2。比如「飞书日历 Skill + 邮件 Skill」，AI 就能「先看日程，再给客户发确认邮件」。

一句话：**Skill 让你的 AI 从「功能机」升级成「智能机」**。

### Skill 的生命周期（先有个概念）

很多新手的第一直觉是「Skill 装上就能用」。其实它不是开关，更像「一个 App 要先被发现、再被点开、跑起来、最后把结果给你」的过程。这一节只让你**记住这些阶段的名字**，每个阶段背后的机制，留给后面两篇讲。

一个 Skill 从被装好到给你结果，大致会经过这几个阶段：

- **发现（Discovery）**：AI 启动时，会先扫一眼所有装好的 Skill，记下「有谁、分别能干嘛」——但只看名片，不看全文。
- **触发（Trigger）**：你说了一句话，AI 判断「这个需求该不该用某个 Skill」。该用就用，不该用就不动。
- **加载（Load）**：决定用之后，AI 才把这份 Skill 的「说明书」真正翻开读进来。
- **执行（Execute）**：AI 按说明书做事，必要时调用脚本或其它工具。
- **输出（Output）**：执行完，把结果交给你——可能是一段文字、一个文件、一次操作。
- **失败（Failure）**：任何一步都可能出岔子：该用没用、读错版本、脚本报错、结果对不上。这是横切的兜底，不是单独的一步。

这 6 个词你先有个印象就够了。想看「发现到底怎么扫、触发到底比什么、加载到底读哪部分、失败时退出码怎么报」——那是机制层面的细节，在 [一个 Skill 是怎样工作的](./06-一个-Skill-是怎样工作的.md) 里展开。本篇只负责让你「知道有这些事」。

## 实例分析：生活中的 Skill

光说概念容易抽象。下面几个例子，都是你日常工作里会真正用到的 Skill。看完你应该能立刻把「Skill 是给 AI 装的 App」这个类比对上号。

### 例子一：飞书日历 Skill

你对着 AI 说：「帮我约明天下午 3 点和小王开个会，1 小时。」

- **没有飞书 Skill 时**：AI 只能口头答应「好的，我提醒你」，但它没法真去改你的日历——因为它没有手伸进飞书。
- **装了飞书日历 Skill 后**：AI 会先被发现到「我有一个飞书日历的 Skill」，触发条件命中后加载它，然后真正调用飞书的接口，在你的日历里建一个会议。你打开飞书一看，日程已经在那了。

这就是「Skill 让 AI 从会说变成会做」。

### 例子二：天气 Skill

你问：「明天苏州天气怎么样？」

- AI 拿这句话，触发到天气 Skill；
- 天气 Skill 调用某个天气接口（这是「动手」的活）；
- 接口返回原始数据，AI 把它整理成「明天苏州，多云转阵雨，18-25 度，建议带伞」这段通顺的话给你。

注意：**「查天气」这件事，大模型自己是干不了的**——它没法联网。联网的活儿是 Skill 配合工具来做的。

### 例子三：代码审查 Skill

你把一段代码贴给 AI：「这段代码帮我看看有没有 Bug。」

- 不用 Skill 时：AI 靠自己的知识「猜」哪里可能有问题，但它不知道你们团队的规范，也不会真去跑测试。
- 用了代码审查 Skill 后：AI 会按这份 Skill 里写好的「审查清单」一条条过，必要时运行测试脚本，最后给你一份结构化的报告：哪些是 Bug、哪些是优化点、严重程度分级。

「审查清单」就是 Skill 里的「知识」，「跑测试」是 Skill 里的「动手」。

### 例子四：邮件 Skill

你说：「给客户发一封报价邮件，附上昨天那份方案。」

- 邮件 Skill 被触发；
- AI 先起草邮件正文（这是它本来就擅长的「说」）；
- 再调用邮件 Skill 的发送能力，把附件和正文真的发出去（这是 Skill 给它的「手」）。

邮件发完，你收到客户回复——这一连串，是 AI + Skill 配合完成的。

从这四个例子里，你应该能提炼出一个共性：**凡是「光靠对话搞不定、需要真去操作某个系统」的事，都是 Skill 的舞台**。

## 常见误解

概念入门篇讲的是「认知」，下面这几条是新手最容易想偏的地方。每条先点破，再纠回来。

### 误解一：以为 Skill 是万能的

装了 Skill 不等于 AI 立刻无所不能。Skill 只在它声明的能力范围内有效——飞书日历 Skill 不会帮你查天气，天气 Skill 不会帮你改代码。AI 不是装了一个 Skill 就「点满所有技能树」，而是「装了哪个，才会哪个」。

### 误解二：以为装了就一定会触发

很多新手装完一个 Skill，问 AI 一个相关问题，结果 AI 没用上，就觉得「这 Skill 坏了」。其实多半是**触发**没命中：你问的话和 Skill 自我介绍的描述对不上，AI 就判断「不需要用它」。想让 Skill 可靠触发，关键是它开头那段「名片」要写得准——这是后面 06 篇的重点。

### 误解三：以为 Skill 和 Plugin 完全是一回事

它们经常指同一份能力，但**叫法随场景变**：在 AI 助手里按需加载时叫 Skill，在某个软件的插件市场里分发时叫 Plugin。说「不是一回事」或「完全是一回事」都不准确，准确的表述是「同一份能力，挂在不同宿主上时有不同叫法」。

### 误解四：以为 Skill 就是「一段提示词」

不是。提示词只是「教 AI 怎么说」，Skill 是一个**文件夹**，里面除了说明（知识），还有可以真正执行的脚本（手脚），以及按需读取的参考资料。提示词是 Skill 的一部分，但 Skill ≠ 提示词。

### 误解五：以为 Skill 装上就一直占着 AI 的「脑容量」

不会。Skill 是「按需加载」的：平时 AI 只记下它的一张名片，等你真的问到相关问题时，才把说明书翻开。所以装 100 个 Skill，也不会一开始就把 AI 的脑子塞满。这点让 Skill 比「一上来就塞一大段提示词」高效得多。

### 误解六：以为 Skill 能干所有事，所以可以不管边界

Skill 也会失败——触发不到、读错版本、脚本缺依赖、结果对不上预期，都是常态。把 Skill 当成「一定能成功」的黑盒，会在它悄悄出错时毫无察觉。建立「Skill 有失败边界」这个认知，是后面学调试、学信任边界的基础。

## 自测题 / 验收

读完这篇，试着回答下面 5 题。能答出 4 题以上，就说明 Skill 的基本概念你建立起来了，可以往下一篇走。

1. 用你自己的话，一句话说清 Skill 是什么——至少用上「AI」和「App」这两个词。
2. Skill 和 Plugin 有什么区别？又有什么联系？用「同一份能力，不同叫法」这个思路解释一遍。
3. 说出 Skill 为什么重要的 4 个理由，并为每个理由举一个你工作中的例子。
4. 列出 Skill 生命周期的几个阶段（发现、触发、加载、执行、输出、失败），每阶段用一句话说说它大致在干嘛。注意：每阶段的**机制细节**不用展开，这是后面两篇的事。

如果你第 5 题答出「不一定，要触发命中才算数」，说明你已经摸到 Skill 运作的门道了。
