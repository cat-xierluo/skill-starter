# 上游同步命令加固设计

> 日期：2026-07-30
> 范围：`.claude/commands/sync-upstream.md` 与临时 Git 仓库演练

## 目标

让 `/sync-upstream` 在同步已有镜像、拉取新 Skill 和处理本地派生版时具备可审计、可回退的明确行为，避免误推上游、覆盖本地补丁或漏拉目录外依赖。

## 方案比较

1. **只加固命令协议并补 Git 演练（采用）**：保持 command 作为 Agent 执行协议，不增加第二套同步 CLI；用自动化临时仓库证明关键 Git 操作可用。
2. **新增完整同步脚本**：执行更确定，但需要维护参数、交互、跨平台文件复制和派生版合并接口，容易与 `skill-manager` 重叠。
3. **扩展为 registry 同步管理器**：可长期自动升级多个来源，但明显超出当前任务，也会把第三方来源策略和 Skill 安装更新体系混在一起。

## 核心设计

同步前先按 `SOURCE-INDEX.md` 把目标分成新增、无本地补丁镜像、派生版三类。remote 的 fetch URL 与用户输入必须一致，并设置独立 push URL 为 `DISABLED`。目标目录有任何未提交、暂存或未跟踪改动时停止。

备份目录采用 `.starter-backups/<UTC时间>-<upstream-short-SHA>/`，每次同步唯一；本地已有目标用 `cp -a` 完整复制，并记录 manifest。镜像和新增目标可精确 checkout `skills/<name>`；派生版只导出 upstream 候选到临时目录，比较后定向合并。`skill-manager` 固定属于派生版，DEC-020、DEC-034 补丁是覆盖禁区。

同步后核对上游根许可证、NOTICE、依赖清单和目录外相对引用，再运行 Skill 自带行为测试及全仓严格检查。失败时把候选移入备份根的 `failed-current/`，恢复原目录并清除 checkout 带来的 index 变化，不删除失败证据。

## 验证设计

自动化测试在隔离临时目录创建两个本地 Git 仓库，不连接网络：

- 设置 remote 的 push URL 为 `DISABLED`，证明 fetch 正常而 push 失败；
- 对已有 Skill 执行精确子树 checkout，证明时间/SHA 备份可完整恢复且工作树回到干净状态；
- 对新增 Skill 执行精确 checkout，再按协议回退，证明不会残留 staged 或工作区文件；
- 静态检查 command 必须包含派生版禁覆盖、目录外依赖、严格门禁和报告要求。

该演练证明 Git 操作与回退路径可执行，不等同于证明所有真实上游结构都兼容。真实同步仍需按目标 Skill 运行自己的测试并核对许可证。
