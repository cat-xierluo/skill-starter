# 写作规范（skill-starter 教程）

本文件是 skill-starter 所有教程文章的统一写作规范。参考资料类文章（`05-参考资料/`）不强制套用教程结构，但术语与事实口径仍遵循本文。

本规范把 Wave 1/2 的 writing-reviewer 教训 codify 成硬规则，避免后续文章重蹈。

## 1. 教程统一最小结构

每篇教程按以下骨架组织（顺序固定，章节标题可微调但语义不变）：

1. **本篇目标**：读完能做什么，3-5 条可检验的「你能……」。
2. **前置知识**：建议先读哪些篇 / 需要什么基础；零基础门槛的命令行等，写「照抄示例即可，无需预先掌握」并指向入门篇，不要假设读者已知。
3. **核心概念**：本文要讲清的关键概念，配表格/类比/正反例。
4. **动手步骤** 或 **实例分析**：见下方「标题名实相符」规则。
5. **常见错误**：每条给一句话命名 + 展开（不要机械编号「错误 1/2/3」）。
6. **自测题 / 验收**：可照着做的小练习。
7. **下一篇**：只突出 1 条主线下一篇，其它入口收敛到 README，避免零基础读者被引诱跳出后不回来。

## 2. 标题名实相符（Wave 1 共性教训）

- **真有操作**（敲命令、建文件、跑脚本）→ 用「动手步骤」。
- **纯讲解 / 案例分析**（讲概念关系、演示流程）→ 用「实例分析」「概念辨析」，**不要硬套「动手步骤」**。
- 一篇内「动手步骤」与「实例分析」的顺序，系列内统一一种（建议**实例先行、动手在后**，零基础读者先看案例更容易进入）。

## 3. 计数准确（Wave 1 Critical 教训）

标题里的数字必须等于正文实际条数：
- 「分成 5 层」→ 正文表格必须正好 5 行；
- 「五对关系」→ 必须正好 5 组「A vs B」；
- 「7 步」→ 必须正好 7 个步骤小节。
定稿前对每个「N 个 / N 步 / N 层」做一遍正文核对。

## 4. 统一示例项目

系列沿用**同一个贯穿小项目**：本地命令行待办脚本 `todo.py`（Python 3 标准库、存 `todos.json`、`add/list/done` 三命令）。用它讲 Git 提交、Agent 协作、Skill 创建、测试、发布，减少读者每篇重新理解背景的成本。涉及密钥/网络时用假凭据（如 `sk-fake-DEMO1234`、`<your-api-key>`）。

## 5. 跨平台范围

命令示例必须标注平台差异：
- macOS（BSD）、Linux（GNU）、Windows（PowerShell / Git Bash）行为不同的命令逐一标注（典型：`ls --help`、退出码、`grep/sed`、路径分隔符、`pip` vs `pip3`、`source` vs `Activate.ps1`）。
- 「最近核对 2026-07」这类时效断言**只在真核对时写**，否则用「截至写作时」软化。
- Windows PowerShell 的常见拦路点（如 `Activate.ps1` 撞 ExecutionPolicy）要在「常见错误」列出解法。

## 6. 术语与去 AI 化

- **术语首次括注**：术语第一次出现补半句解释，不依赖读者点链接（Wave 1/2 共性教训：宿主程序、frontmatter、退出码、lint、hooks、JSON 等都曾漏）。
- **收尾别都用「不是 X 而是 Y」**（Wave 1 六篇全这样，已同质）。换形式：练习题 / 场景带入 / 一句具体行动建议。
- **占位符用尖括号**（`<your-token>`），示例用真实可敲字符串（`ls no-such-file.txt` 而非 `ls 不存在的文件`）。
- 不写「综上所述」「值得注意的是」等套话；行文朴实。

## 7. 交叉引用

- 只用相对链接，且**只指向仓库内真实存在的文件**（写前确认目标存在）。
- 下一篇给具体链接；若目标篇未发布，明确写「（暂未发布）」。
- 引用第三方事实（Skill 来源、许可证、issue）以 `docs/SOURCE-INDEX.md` 为准，不编造 URL/SHA。

## 8. 事实与不确定

- 命令、概念、版本号要准确；不确定的标「需作者确认」或「待核对」，不写死。
- 法律 / 事实专业判断不替读者裁决。

## 9. 长度

教程级深度 2500-4500 字；概念总览篇可更长。宁可少而准，不要凑篇幅（Wave 1「7 要素 vs 7 步骤重复」教训：同信息不要讲两遍）。
