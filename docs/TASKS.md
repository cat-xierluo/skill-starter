## P2：内容与使用体验验收

- [ ] **T-005｜就绪｜按写作规范复核较早教程**
  - 目标：零基础读者能看懂文章目标、前置知识、操作步骤、常见错误和验收方式。
  - 范围：优先复核概念入门 02–04、工具指南 01–05、AI 协作 01–04；教程按 `WRITING-GUIDE.md` 检查，参考资料保留其自身体裁。
  - 非目标：不为了形式统一强行改写参考索引；不在本任务中新增课程主题。
  - 验收：形成文章级检查结果；需要补写的教程具备目标、前置、步骤、错误、自测/验收和下一步；同步 `CONTENT-MATRIX.md` 的质量状态。
  - 当前证据：新增主线文章普遍符合规范，较早文章尚未完成同口径复核；README 已避免“每篇都已统一”的绝对表述。

- [ ] **T-006｜就绪｜为教程关键命令和示例建立可复跑证据**
  - 目标：证明读者按教程执行能够得到文中声明的结果，而不只证明 Markdown 和脚本语法合法。
  - 范围：优先覆盖贯穿案例 `todo.py`、纯说明型 Skill、带脚本 Skill、多 Skill 编排、发布与回滚；区分自动测试、真实 Agent 测试和真人走查。
  - 非目标：静态检查通过不能替代行为证据；不把单次样例扩大为跨平台稳定性结论。
  - 验收：每个核心实践至少有一份可复现命令、预期输出和失败路径；自动化部分在干净临时目录通过；无法自动化的项目明确标记验证责任。
  - 当前证据：统一入口已有 30 个工程回归测试，但尚未覆盖教程中的全部关键命令和示例输出。

- [ ] **T-007｜就绪｜建立一个 starter 原创的端到端标准示例 Skill**
  - 目标：提供一个能从需求、触发、实现、测试到维护完整展示的可运行样例。
  - 范围：包含触发与负向触发、输入输出、真实脚本与输出、错误路径、测试、许可证、来源说明和维护文档。
  - 非目标：先完成一个教学问题明确的标准示例，不批量制作只更换业务名称的垂直示例。
  - 验收：在独立临时目录安装和运行成功；正常与错误输入均有可观察结果；严格检查通过；后续任务 T-008、T-009 可基于它执行。
  - 当前证据：模板和三层教程已经存在，但还没有 starter 原创、完整可运行的标准示例。

- [ ] **T-008｜阻塞｜执行模板与标准示例的真实 Agent 验证**
  - 目标：验证 Agent 对 Skill 描述、触发边界和错误处理的真实理解。
  - 范围：无旧会话上下文地测试“应该触发、不应该触发、正常执行、错误输入”四类场景，并保存输入、实际行为和判断依据。
  - 非目标：不以 frontmatter 静态校验或当前会话自报替代前向测试。
  - 验收：四类场景均有可复查证据；失败场景回写为模板或示例任务，不掩盖近失误。
  - 阻塞条件：依赖 T-007 的标准示例；还需具备可隔离启动的真实 Agent 环境。

- [ ] **T-009｜阻塞｜编写“从复制模板到发布”的逐步实验**
  - 目标：让读者在完成一次实验后能够独立产出可验证 Skill。
  - 范围：以 T-007 标准示例为唯一案例，覆盖复制、改写、运行、测试、版本、发布和回滚。
  - 非目标：不重复 06/07/08 三篇教程的全部概念说明；实验聚焦操作和验收。
  - 验收：在干净目录从头执行成功；每一步有输入、预期结果和失败恢复；文内链接通过严格检查。
  - 阻塞条件：依赖 T-007 稳定后才能定稿。

- [ ] **T-010｜阻塞｜组织零基础真人读者走查**
  - 目标：验证学习顺序、完成时间和独立操作能力，发现 AI 与作者无法自行识别的理解障碍。
  - 范围：每批至少邀请一名没有 Skill 开发经验的读者，记录卡点、完成时间、求助点和未完成步骤。
  - 非目标：AI 模拟读者、链接检查和单元测试不能替代本验收。
  - 验收：至少完成一轮真实走查；问题转成新的任务卡；修订后记录复验结果。
  - 阻塞条件：需要维护者安排真人读者和可记录反馈的时间窗口。
